## 一、设计 System 提示词

写提示词之前先想清楚:**AI 要完成哪些功能**。本项目四大功能:

```
1. 课程推荐   2. 课程购买   3. 课程咨询   4. 知识讲解
```

### 1.1 提示词结构(可直接套用)

```
角色:你作为在线教育平台资深客服代表兼讲师,根据学员需求调用知识库中的课程信息,
     推荐合适课程,并解答课程内容与知识点疑问。

技能 1:课程推荐
1. 判断信息是否齐全:年龄、学历、是否有编程基础;缺就礼貌追问
2. 学员没说方向 → 追问;仍没方向 → 优先推荐学习人数多的课程
3. 信息齐全 → 去知识库匹配课程,拿课程 id,调用 queryCourseById 查详情后推荐(单门/多门)
4. 知识库没有该方向 → 明确告知,并推荐其他课程
5. 信息与课程要求不匹配 → 说明原因后再推荐
6. 必须通过 queryCourseById 工具查出课程后才能返回课程数据

技能 2:课程购买
1. 判断本次会话是否已明确课程 / 是否已为学员推荐过
2. 已明确 → 调用 prePlaceOrder 工具直接进入预下单
3. 未明确 → 引导进入推荐流程,或询问买哪门课
4. 支持买一门或多门

技能 3:课程咨询
1. 问课程内容 → 知识库匹配课程拿 id 查详情,回复要全面并引导报名
2. 查不到 → 礼貌告知并建议联系人工客服(your-support-phone)
3. 问有效期 → 用「当前时间 {now} + 有效期」算出到期日;999 天视为永久有效

技能 4:知识讲解
1. IT 知识点问题 → 详细讲解 + 给示例

限制:
- 推荐课程只能来自知识库,坚决不能编造
- 只能回答课程与 IT 知识相关问题,其它礼貌拒绝并引导
- 学员问课程 ID → 告知无法提供,引导其它问题
```

### 1.2 提示词放 Nacos(支持热更新)

提示词经常要调,**写死在代码里就得改一次发一次版**。做法:提示词放 Nacos,代码里监听变更。

```yaml
demo:
  ai:
    prompt:
      system:
        chat:
          data-id: system-chat-message.txt
          group: DEFAULT_GROUP
          timeout-ms: 20000
```

```java
@Slf4j
@Getter
@Configuration
@RequiredArgsConstructor
public class SystemPromptConfig {
    private final NacosConfigManager nacosConfigManager;
    private final AIProperties aiProperties;

    // 原子引用:线程安全(CAS),多线程读写不慌
    private final AtomicReference<String> chatSystemMessage = new AtomicReference<>();

    @PostConstruct
    public void init() {
        loadConfig(aiProperties.getSystem().getChat(), chatSystemMessage);
    }

    private void loadConfig(AIProperties.System.Chat chatConfig, AtomicReference<String> target) {
        try {
            String dataId = chatConfig.getDataId();
            String group = chatConfig.getGroup();
            // 1. 主动读一次
            String config = nacosConfigManager.getConfigService()
                    .getConfig(dataId, group, chatConfig.getTimeoutMs());
            target.set(config);
            // 2. 加监听器:配置改了自动更新 → 热更新
            nacosConfigManager.getConfigService().addListener(dataId, group, new Listener() {
                @Override public Executor getExecutor() { return null; }   // 用 Nacos 默认线程池
                @Override public void receiveConfigInfo(String info) { target.set(info); }
            });
        } catch (Exception e) {
            log.error("加载配置失败", e);
        }
    }
}
```

### 1.3 应用提示词(带模板参数)

```java
return chatClient.prompt()
        .system(s -> s
                .text(systemPromptConfig.getChatSystemMessage().get())   // 提示词
                .param("now", DateUtil.now()))                           // 填充 {now} 占位符
        .user(question)
        .stream()
        .chatResponse()
        .map(...);                                                       // 同上一篇:转事件
```

> 效果:提示词里写 `{now}`,代码里 `.param("now", ...)` 填值——**提示词当模板用**,业务数据动态注入。

## 二、停止生成

### 2.1 原理(先想清楚,再写代码)

- 大模型一旦开始生成,**程序侧无法真正"打断"模型**;
- 能控制的只是**输出流**:把 Flux 流截断,前端就不再收到内容;
- ⚠️ 所以:**"停止"省的是前端体验,不一定省 token 费用**(模型可能还在后台生成)。

### 2.2 接口

```
POST /chat/stop?sessionId=f1dbf6ca...
```

### 2.3 实现:用一个"生成状态标记"控制流

```java
// key = sessionId,value = 是否继续生成(线程安全 Map;分布式环境可换 Redis)
private static final Map<String, Boolean> GENERATE_STATUS = new ConcurrentHashMap<>();

@Override
public Flux<ChatEventVO> chat(String question, String sessionId) {
    return chatClient.prompt()
            .user(question)
            .stream()
            .chatResponse()
            .doFirst(() -> GENERATE_STATUS.put(sessionId, true))           // 1. 开始:标记"生成中"
            .doOnError(t -> GENERATE_STATUS.remove(sessionId))              // 2. 异常:清标记
            .doOnComplete(() -> GENERATE_STATUS.remove(sessionId))          // 3. 完成:清标记
            .takeWhile(r -> GENERATE_STATUS.getOrDefault(sessionId, false)) // 4. 关键:标记没了就终止流
            .map(r -> ChatEventVO.builder()
                    .eventData(r.getResult().getOutput().getText())
                    .eventType(ChatEventTypeEnum.DATA.getValue())
                    .build())
            .concatWith(Flux.just(STOP_EVENT));
}

@Override
public void stop(String sessionId) {
    GENERATE_STATUS.remove(sessionId);     // 移除标记 → takeWhile 返回 false → 流终止
}
```

> 核心就一句:**`takeWhile` 每来一条数据都问一次"还继续吗?",stop 时把标记删掉,流就断了。**

## 三、本节速记

1. 业务提示词按"**角色 + 各技能流程 + 限制**"组织,工具只在流程里点名、不列清单;
2. 提示词放 **Nacos + 监听器**实现热更新,代码里用 `AtomicReference` 保证线程安全;
3. 提示词当**模板**,`{now}` 这类占位符由 `.param()` 动态填;
4. 停止生成 = **标记 + `takeWhile`**:删标记即终止流;注意它不保证省模型费用;
5. 分布式部署时,`GENERATE_STATUS` 这种内存标记要换成 Redis(多实例共享)。
