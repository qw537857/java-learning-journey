# MCP 概述:模型上下文协议(2026-09-11)

> 来源:AI 课程导图(20 Spring AI MCP)整理,面向 Java 初级工程师。
> 目标:搞懂 MCP 是什么、和 Tool Calling 有什么区别、两种通信机制怎么选。

---

## 一、什么是 MCP

- **MCP(Model Context Protocol,模型上下文协议)**:一种**标准化协议**;
- **2024 年 11 月底由 Anthropic 推出**,目标是**统一大模型与外部数据源/工具之间的通信协议**;
- 解决的问题:让 AI 应用能**安全地访问和操作本地及远程数据**,等于给 AI 提供"连接万物的接口"。

**没有 MCP 时**:要对接 N 个三方服务,就得按 N 套标准和协议分别写适配;
**有了 MCP 后**:大家都按同一套标准协议交互,适配一次、处处可用。

> 看上去和 Tool Calling 差不多(都是增强大模型能力),**不一样的是:MCP 是标准,更通用**。

---

## 二、MCP 与 Tool Calling 的区别

既然有 Tool Calling,为什么还要 MCP?两个场景说明问题:

1. **跨语言不通**:用 SpringAI(Java)写的 Tool,能直接放到 Python 项目用吗?——不能,得用 Python 重写一遍;
2. **跨项目不复用**:每个新项目都要重新写"天气查询、商品检索、下单"这些通用工具,重复劳动。

**MCP 的解法**:把常用工具按 MCP 标准做成**服务(Server)**,任何支持 MCP 的智能体都能直接调用 → **通用、可复用**。

| 对比 | Tool Calling | MCP |
|------|--------------|-----|
| 本质 | 大模型调用本地函数 | 基于标准协议调用工具服务 |
| 通用性 | 绑定语言/项目 | 跨语言、跨项目复用 |
| 复用性 | 每个项目重写 | 写一次,到处调用 |

> 关键理解:**MCP 的底层实现本质仍是 Tool Calling**,只是调用与传输基于 MCP 标准协议。

---

## 三、MCP 通信机制(两种)

| 机制 | 说明 | 适用场景 |
|------|------|----------|
| **Stdio**(标准输入输出) | 本地进程间通信(IPC) | 操作**本地**软件/文件 |
| **SSE**(Server-Sent Events) | 远程网络通信(基于 HTTP) | 跨网络实时传输、远程资源、分布式部署 |

---

## 四、SpringAI 对 MCP 的支持

SpringAI 封装了 MCP 的客户端与服务端,简化 Java 项目开发(参考官方 Model Context Protocol 文档)。

### 4.1 MCP Client 负责什么

- 与 MCP 服务器建立/管理连接;**协议版本与能力协商**;
- 消息传输与 **JSON-RPC** 通信;
- **工具发现与执行**、资源访问管理、提示系统交互;
- 可选:根管理、采样、同步/异步操作;
- 传输方式:stdio、Java HttpClient SSE、WebFlux SSE(响应式)。

### 4.2 MCP Server 负责什么

- 服务端协议实现;**工具暴露与发现**;基于 URI 的资源管理;提示模板;
- 与客户端能力协商;**结构化日志与通知**;并发连接管理;同步/异步 API;
- 传输实现:stdio、Servlet SSE、WebFlux SSE、WebMVC SSE。

---

## 五、本节速记

1. MCP = 大模型与外部工具的**标准化协议**(Anthropic,2024.11);
2. 它让工具**跨语言、跨项目复用**(Java 写的工具 Python 也能用);
3. 本质仍是 Tool Calling,只是走标准协议;
4. 两种通信:**Stdio 管本地**、**SSE 管远程**;
5. SpringAI 内置 MCP Client/Server 支持,Java 开发者开箱可用。
