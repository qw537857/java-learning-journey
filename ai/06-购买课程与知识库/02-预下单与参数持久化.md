## 一、预下单功能

### 1.1 实现思路(和课程查询几乎一样)

```
1. 定义 OrderTools:调用交易服务的 prePlaceOrder(课程ids)
2. 调用交易服务前要在 UserContext 里设置"当前用户 id"(否则 Feign 调用 401)
   用户 id 通过 ToolContext 从 ChatService 传进来
3. 把 OrderTools 注册到 ChatClient
4. 工具名与参数描述统一放常量类
```

### 1.2 结果类 PrePlaceOrder

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class PrePlaceOrder {
    @JsonPropertyDescription("课程数量")            private int count;
    @JsonPropertyDescription("订单总金额")          private double totalAmount;
    @JsonPropertyDescription("最大优惠金额")        private double discountAmount;
    @JsonPropertyDescription("优惠券名称")          private String couponName;
    @JsonPropertyDescription("实付金额")            private double payAmount;
    @JsonPropertyDescription("课程id列表")          private List<Long> courseIds;
    @JsonPropertyDescription("订单id")             private Long orderId;
    @JsonPropertyDescription("优惠券id")            private Long couponId;

    public static PrePlaceOrder of(OrderConfirmVO vo) {
        double totalAmount = Optional.ofNullable(vo.getTotalAmount())
                .map(n -> n.doubleValue() / 100d)                 // 分 → 元
                .map(n -> NumberUtil.round(n, 2).doubleValue())
                .orElse(0.0d);

        double discountAmount = Optional.ofNullable(CollUtil.getFirst(vo.getDiscounts()))
                .map(CouponDiscountDTO::getDiscountAmount)
                .map(n -> n.doubleValue() / 100d)
                .map(n -> NumberUtil.round(n, 2).doubleValue())
                .orElse(0.0d);

        String couponName = Optional.ofNullable(CollUtil.getFirst(vo.getDiscounts()))
                .map(d -> {
                    List<String> rules = d.getRules();
                    int size = CollUtil.size(rules);
                    return size >= 2
                            ? StrUtil.format("叠加{}券:【优惠{}元】", size, discountAmount)
                            : StrUtil.format("单券:【{}】", CollUtil.getFirst(rules));
                })
                .orElse("");

        double payAmount = NumberUtil.round(totalAmount - discountAmount, 2).doubleValue();
        List<Long> courseIds = CollStreamUtil.toList(vo.getCourses(), OrderCourseDTO::getId);
        Long couponId = Optional.ofNullable(CollUtil.getFirst(vo.getDiscounts()))
                .map(CouponDiscountDTO::getIds()).map(CollUtil::getFirst).orElse(null);

        return PrePlaceOrder.builder()
                .count(CollUtil.size(vo.getCourses()))
                .totalAmount(totalAmount)
                .discountAmount(discountAmount)
                .couponName(couponName)
                .payAmount(payAmount)
                .courseIds(courseIds)
                .orderId(vo.getOrderId())
                .couponId(couponId)
                .build();
    }
}
```

> 观察:大量使用 `Optional` + `Hutool`——**空值安全 + 一行式转换**,业务代码不堆 if。

### 1.3 OrderTools

```java
@Component
@RequiredArgsConstructor
public class OrderTools {

    private final TradeClient tradeClient;                  // 交易服务 Feign 客户端

    @Tool(description = Constant.Tools.PRE_PLACE_ORDER)
    public PrePlaceOrder prePlaceOrder(
            @ToolParam(description = Constant.ToolParams.COURSE_IDS) List<Number> ids,
            ToolContext toolContext) {

        // 1. 设置用户上下文(Feign 调用要带身份,否则 401)
        UserContext.setUser(Convert.toLong(toolContext.getContext().get(Constant.USER_ID)));

        // 2. 大模型传来的可能是 Integer,统一转 Long 再调服务
        var orderConfirmVO = tradeClient.prePlaceOrder(
                CollStreamUtil.toList(ids, Number::longValue));

        // 3. 结果存入保持器,供流末尾回传前端
        return Optional.ofNullable(orderConfirmVO)
                .map(PrePlaceOrder::of)
                .map(prePlaceOrder -> {
                    String requestId = Convert.toStr(toolContext.getContext().get(Constant.REQUEST_ID));
                    String field = StrUtil.lowerFirst(prePlaceOrder.getClass().getSimpleName());
                    ToolResultHolder.put(requestId, field, prePlaceOrder);
                    return prePlaceOrder;
                })
                .orElse(null);
    }
}
```

## 二、Bug:卡片参数没进历史记录

### 2.1 现象

- 前端卡片正常显示(因为 1003 事件带着数据);
- 但**翻历史记录时,卡片数据没了**——Redis 里存的助手消息 `params` 是空的:

```json
{
  "messageType": "ASSISTANT",
  "textContent": "您的订单已成功创建…",
  "params": {}                       ← 卡片数据没存上
}
```

原因:保存消息到 Redis 时,**只保存了文本**,没保存 `ToolResultHolder` 里的结构化参数。

### 2.2 难点与思路

| 难点 | 思路 |
|------|------|
| 保存时怎么拿到参数? | 参数在 `ToolResultHolder` 里,key 是 **requestId** |
| 但保存消息时**只有 messageId**,没有 requestId | 建立 **messageId → requestId** 的映射(还是用 ToolResultHolder 当通用容器) |
| 反序列化时 AssistantMessage 没有 params 字段 | **继承 AssistantMessage**,扩展一个 params 属性 |

### 2.3 实现

**① 流里记录"消息 id → 请求 id"(最后一条数据时)**

```java
.map(chatResponse -> {
    String finishReason = chatResponse.getResult().getMetadata().getFinishReason();
    if (StrUtil.equals(Constant.STOP, finishReason)) {
        String messageId = chatResponse.getMetadata().getId();
        ToolResultHolder.put(messageId, Constant.REQUEST_ID, requestId);   // ★ 建立映射
    }
    String text = chatResponse.getResult().getOutput().getText();
    outputBuilder.append(text);
    return ChatEventVO.builder().eventData(text)
            .eventType(ChatEventTypeEnum.DATA.getValue()).build();
})
```

**② 序列化时:由 messageId 找 requestId,再取参数存进 params**

```java
public static String toJson(Message message) {
    MyMessage my = BeanUtil.toBean(message, MyMessage.class);
    my.setTextContent(message.getText());
    if (message instanceof AssistantMessage assistantMessage) {
        my.setToolCalls(assistantMessage.getToolCalls());
        // messageId → requestId → 参数
        String messageId = Convert.toStr(assistantMessage.getMetadata().get(Constant.ID));
        String requestId = Convert.toStr(ToolResultHolder.get(messageId, Constant.REQUEST_ID));
        Map<String, Object> params = ToolResultHolder.get(requestId);
        if (MapUtil.isNotEmpty(params)) {
            my.setParams(params);                       // ★ 参数随消息一起持久化
        }
        ToolResultHolder.remove(messageId);             // 用完清理
    }
    if (message instanceof ToolResponseMessage trm) {
        my.setToolResponses(trm.getResponses());
    }
    return JSONUtil.toJsonStr(my);
}
```

**③ 反序列化:自定义 AssistantMessage 子类带 params**

```java
@Setter
@Getter
public class MyAssistantMessage extends AssistantMessage {
    private Map<String, Object> params;

    public MyAssistantMessage(String content, Map<String, Object> properties,
                              List<ToolCall> toolCalls, List<Media> media,
                              Map<String, Object> params) {
        super(content, properties, toolCalls, media);
        this.params = params;
    }
}
```

```java
case ASSISTANT -> new MyAssistantMessage(
        my.getTextContent(), my.getMetadata(), my.getToolCalls(), my.getMedia(), my.getParams());
```

**④ 查询会话详情时把 params 一起返回**

```java
.map(message -> {
    if (message instanceof MyAssistantMessage m) {
        return MessageVO.builder()
                .content(message.getText())
                .type(MessageTypeEnum.valueOf(message.getMessageType().name()))
                .params(m.getParams())        // ★ 历史卡片数据
                .build();
    }
    return MessageVO.builder()
            .content(message.getText())
            .type(MessageTypeEnum.valueOf(message.getMessageType().name()))
            .build();
})
```

## 三、本节速记

1. 预下单 = **工具调用已有交易服务**,注意在 ToolContext 里传 userId(Feign 要身份);
2. 大模型传的数字类型可能是 Integer,调用前统一转 Long;
3. Bug 根因:**消息落库只存了文本,结构化参数(卡片)没存**;
4. 解法链:**messageId → requestId → ToolResultHolder** 取参数,写进 params 持久化;
5. 反序列化要**继承 AssistantMessage 扩展字段**,否则参数读不回来;
6. 通用心法:**凡是"给前端的结构化数据",都要考虑"历史回看时还在不在"**。
