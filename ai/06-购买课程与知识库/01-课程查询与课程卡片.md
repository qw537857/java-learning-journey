# 课程查询与"课程卡片"(2026-09-12)

> 来源:AI 课程导图(11 购买课程与知识库)整理,面向 Java 初级工程师。
> 目标:用 Tool Calling 实现"按课程 id 查询课程",并把工具结果作为**结构化数据**传给前端渲染成卡片。

---

## 一、需求

```
用户:查询课程,课程 id 为 1880000000000000001
AI  :(调用工具查到课程) + 前端展示【课程卡片】(名称/价格/有效期/适用人群,可点击跳详情)
```

"大模型只产出文字,但卡片需要结构化数据"——这就是本篇的核心命题。

## 二、课程查询(基础 Tool)

### 2.1 复用已有微服务

项目里已有**课程微服务**,并提供了 `baseInfo(课程id)` 接口;AI 服务通过 **Feign Client** 调它(不用关心内部实现,知道有这接口就行)。

> 微服务协作心法:**AI 服务不重复造轮子**,需要数据就调已有服务的接口。

### 2.2 定义返回结果类(Tool 的返回值)

```java
@Data
@Builder
@NoArgsConstructor
@AllArgsConstructor
public class CourseInfo {
    @JsonPropertyDescription("课程id")
    private Long id;
    @JsonPropertyDescription("课程名称")
    private String name;
    @JsonPropertyDescription("课程价格,单位为元,货币为人民币")
    private double price;
    @JsonPropertyDescription("课程学习有效期,单位:月")
    private Integer validDuration;
    @JsonPropertyDescription("适用人群,例如:初学者")
    private String usePeople;
    @JsonPropertyDescription("课程详细介绍")
    private String detail;

    /** DTO → CourseInfo:顺便把"分"换算成"元"、四舍五入保留两位 */
    public static CourseInfo of(CourseBaseInfoDTO dto) {
        if (dto == null) return null;
        CourseInfo info = BeanUtil.toBeanIgnoreError(dto, CourseInfo.class);
        info.setPrice(Optional.ofNullable(dto.getPrice())
                .map(n -> n.doubleValue() / 100d)                 // 分 → 元
                .map(n -> NumberUtil.round(n, 2).doubleValue())   // 保留两位
                .orElse(0.0d));
        return info;
    }
}
```

> `@JsonPropertyDescription` 会把字段含义写进提示词,让模型理解返回值——**返回对象的字段也要"会说话"**。

### 2.3 常量类(别把字符串散落各处)

### 2.4 Tool 实现

```java
@Component
@RequiredArgsConstructor
public class CourseTools {

    private final CourseClient courseClient;      // Feign 客户端

    @Tool(description = Constant.Tools.QUERY_COURSE_BY_ID)
    public CourseInfo queryCourseById(
            @ToolParam(description = Constant.ToolParams.COURSE_ID) Long courseId) {
        return Optional.ofNullable(courseId)
                .map(id -> CourseInfo.of(courseClient.baseInfo(id)))
                .orElse(null);
    }
}
```

## 三、课程卡片:把工具结果传给前端

### 3.1 思路(想清楚这三步)

```
问题:工具的执行结果已经给了大模型,流式输出时我们怎么再拿一份给前端?
      (答案:全局容器 + requestId)
```

```
1. 每次请求生成一个 requestId
2. Tool 执行完 → 把结果放进"结果保持器"(key = requestId)
3. 流输出到最后 → 按 requestId 取出结果,作为 PARAM 事件(1003)追加进流
```

> 为什么不用 sessionId 关联?**同一个会话可能有并发请求**,sessionId 会串数据 → 必须用**每次请求唯一的 requestId**。

### 3.2 工具结果保持器

```java
/** 工具结果保持器:requestId ↔ {字段名: 结果} */
public class ToolResultHolder {
    private static final Map<String, Map<String, Object>> HANDLER_MAP = new ConcurrentHashMap<>();
    private ToolResultHolder() { }

    public static void put(String key, String field, Object result) {
        Assert.notNull(key, "key is not null!");
        Assert.notNull(field, "field is not null!");
        HANDLER_MAP.computeIfAbsent(key, k -> new HashMap<>()).put(field, result);
    }
    public static Map<String, Object> get(String key) { return key == null ? null : HANDLER_MAP.get(key); }
    public static Object get(String key, String field) {
        return Optional.ofNullable(HANDLER_MAP.get(key)).map(m -> m.get(field)).orElse(null);
    }
    public static void remove(String key) { HANDLER_MAP.remove(key); }
}
```

> 设计:外层 Map 用 requestId,**内层 Map 存多个结果**(比如一次查了 3 门课)→ 前端能渲染多张卡片。

### 3.3 Tool 里存结果(通过 ToolContext 拿 requestId)

```java
@Tool(description = Constant.Tools.QUERY_COURSE_BY_ID)
public CourseInfo queryCourseById(@ToolParam(description = Constant.ToolParams.COURSE_ID) Long courseId,
                                  ToolContext toolContext) {
    return Optional.ofNullable(courseId)
            .map(id -> CourseInfo.of(courseClient.baseInfo(id)))
            .map(info -> {
                // 从工具上下文取出 requestId
                String requestId = Convert.toStr(toolContext.getContext().get(Constant.REQUEST_ID));
                // 字段名:courseInfo_1880533…(同一请求可存多条)
                String field = StrUtil.format("{}_{}",
                        StrUtil.lowerFirst(CourseInfo.class.getSimpleName()), info.getId());
                ToolResultHolder.put(requestId, field, info);
                return info;
            })
            .orElse(null);
}
```

### 3.4 流里带上 requestId + 末尾追加结果

```java
String requestId = IdUtil.fastSimpleUUID();

return chatClient.prompt()
        .system(...)
        .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, conversationId))
        .toolContext(Map.of(Constant.REQUEST_ID, requestId))     // ★ 传给 Tool
        .user(question)
        .stream()
        .chatResponse()
        // ... doFirst/doOnError/doOnComplete/doOnCancel/takeWhile 同上篇
        .map(chatResponse -> {
            String text = chatResponse.getResult().getOutput().getText();
            outputBuilder.append(text);
            return ChatEventVO.builder()
                    .eventData(text).eventType(ChatEventTypeEnum.DATA.getValue()).build();
        })
        .concatWith(Flux.defer(() -> {                           // ★ 延迟到流结束时执行
            Map<String, Object> map = ToolResultHolder.get(requestId);
            if (MapUtil.isNotEmpty(map)) {
                ToolResultHolder.remove(requestId);              // 用完即删,防内存泄漏
                ChatEventVO paramEvent = ChatEventVO.builder()
                        .eventData(map)
                        .eventType(ChatEventTypeEnum.PARAM.getValue())
                        .build();                                // 1003 参数事件
                return Flux.just(paramEvent, STOP_EVENT);
            }
            return Flux.just(STOP_EVENT);
        }));
```

```json
data:{"eventData":{"courseInfo_1880533253575225346":{"id":"1880533253575225346","name":"Java零基础入门","price":199.0,"validDuration":9999,"usePeople":"有Java基础","detail":"…"}},"eventType":1003}
```

### 3.5 小结(本节的四个知识点)

1. 调用已有微服务(Feign)拿数据;
2. 字符串统一进**常量类**;
3. **结构化数据**由后端组装,不靠大模型编;
4. **toolContext 传参 + ToolResultHolder 收集结果 + 流末尾追加**,这套组合解决"工具结果如何回传前端"。

---

## 四、本节速记

1. Tool 返回值用带 `@JsonPropertyDescription` 的对象,**让模型看得懂、前端拿得到**;
2. 工具结果回传前端 = **requestId + 结果容器 + 流末尾 PARAM 事件**(不能只用 sessionId,会并发串数据);
3. `Flux.defer` 保证**流结束时**才去取结果;取完 `remove` 防内存泄漏;
4. 字段命名 `courseInfo_{id}`,一个请求可携带多个结果 → 前端渲染多张卡片;
5. 单位换算(分→元)在服务端做,并在字段描述里写清单位。
