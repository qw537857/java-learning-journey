# 五大业务智能体(2026-09-11)

> 来源:AI 课程导图(12 多智能体协同工作)整理,面向 Java 初级工程师。
> 目标:逐个看清路由、推荐、购买、咨询、知识五个智能体——**提示词怎么写、挂了哪些工具与 Advisor**。
> 说明:案例背景为通用"在线教育 AI 助理",提示词已做通用化改写。

---

## 一、总览:五个智能体的分工

| 智能体 | 类型 | 职责 | 关键配置 |
|--------|------|------|----------|
| 路由 | ROUTE | 意图识别,输出意图编号 | 只需提示词 |
| 推荐 | RECOMMEND | 收集信息 → 匹配课程 → 推荐 | RAG + 课程工具 |
| 购买 | BUY | 预下单 | 订单工具 + 用户上下文 |
| 咨询 | CONSULT | 课程信息答疑 | RAG + 课程工具 + 时间参数 |
| 知识 | KNOWLEDGE | IT 知识点讲解 | 只需提示词 |

---

## 二、路由智能体(意图分析师)

**提示词要点**(存放在配置中心,支持热更新):

```
# 角色:AI 意图分析师
## 能力
1. 识别用户意图并匹配编号:
   - RECOMMEND(课程推荐)
   - BUY(课程购买)
   - CONSULT(课程咨询)
   - KNOWLEDGE(知识讲解)
2. 特殊场景:
   - 关键词触发:BUY(确认购买/下单/是的确认)、RECOMMEND(含年龄/学历/兴趣)、CONSULT(课程信息/能否学会)
   - 问候语(你好/您好)要礼貌回应
3. 非相关问题礼貌拒答
## 输出
- 匹配到意图 → 只返回编号
- 问候 → "您好!有什么可以帮您?"
- 无匹配 → 自然语言回复
## 示例
输入:20岁本科想学Java → RECOMMEND
输入:现在要下单 → BUY
输入:java课程我能学会吗 → CONSULT
输入:你好 → 您好!有什么可以帮您?
输入:今天天气 → 抱歉,我只处理课程相关问题
```

**代码极简**(提示词 + 类型就够):

```java
@Component
@RequiredArgsConstructor
public class RouteAgent extends AbstractAgent {
    private final SystemPromptConfig systemPromptConfig;

    @Override
    public String systemMessage() { return systemPromptConfig.getRouteAgentSystemMessage().get(); }

    @Override
    public AgentTypeEnum getAgentType() { return AgentTypeEnum.ROUTE; }
}
```

### 提示词配置的工程做法(可热更新)

```java
@Data
@Configuration
@ConfigurationProperties(prefix = "demo.ai.prompt")
public class AIProperties {

    @Data
    public static class System {

        private Chat buyAgent;         // 购买智能体
        private Chat consultAgent;     // 咨询智能体
        private Chat knowledgeAgent;   // 知识智能体

        @Data

            private String dataId;                       // 配置中心里的文件名
            private String group = "DEFAULT_GROUP";
            private long timeoutMs = 20000L;
        }
    }
}
```

```java
@Component
public class SystemPromptConfig {
    // 用原子引用保证线程安全,配合配置中心监听实现热更新
    private final AtomicReference<String> routeAgentSystemMessage = new AtomicReference<>();

    @PostConstruct
    public void init() {
        loadConfig(aiProperties.getSystem().getRouteAgent(), routeAgentSystemMessage);
        // ... 其余智能体同理
    }
}
```

> 把提示词放**配置中心(Nacos)**而不是硬编码:改提示词不用发版,运维友好。

## 三、推荐智能体(带 RAG + 工具)

**提示词核心逻辑**:

```
# 角色:在线教育客服 & 讲师
## 核心职责:分步精准推荐(信息采集 → 课程匹配 → 执行推荐)
## 强制流程
1. 信息采集(必须优先):年龄、最高学历、编程基础,缺一不可,缺失就礼貌追问
2. 课程匹配:必须通过"课程 id 查询课程"后再输出;匹配顺序:精准匹配 → 向下兼容 → 关联领域 Top3
3. 推荐执行:必须包含数据关联说明与课程适配点;禁止推荐未经数据验证的课程
## 关键规则
- 未收齐三项数据前禁用推荐功能
- 发现矛盾数据(如"12岁硕士")需确认
- 无匹配时提供"人工咨询"入口
- 必须输出课程 id、价格、介绍
```

**代码:一个智能体同时挂 RAG 与工具**:

```java
@Component
@RequiredArgsConstructor
public class RecommendAgent extends AbstractAgent {
    private final SystemPromptConfig systemPromptConfig;
    private final VectorStore vectorStore;
    private final CourseTools courseTools;

    @Override
    public AgentTypeEnum getAgentType() { return AgentTypeEnum.RECOMMEND; }

    @Override
    public String systemMessage() { return systemPromptConfig.getRecommendAgentSystemMessage().get(); }

    /** RAG 检索增强 */
    @Override
    public List<Advisor> advisors() {
        var qaAdvisor = QuestionAnswerAdvisor.builder(vectorStore)
                .searchRequest(SearchRequest.builder().similarityThreshold(0.6d).topK(6).build())
                .build();
        return List.of(qaAdvisor);
    }

    /** 工具集 */
    @Override
    public Object[] tools() { return new Object[]{courseTools}; }

    /** 给工具传上下文参数(如 requestId) */
    @Override
    public Map<String, Object> toolContext(String sessionId, String requestId) {
        return Map.of("requestId", requestId);
    }
}
```

> 对比:之前的增强型智能体是"全局挂工具";现在是**按智能体挂**——推荐智能体用 RAG+课程工具,购买智能体用订单工具,互不干扰。

## 四、购买智能体(工具 + 用户上下文)

**提示词要点**:

```
# 角色:资深客服代表 & 讲师,职责是协助学员购买课程
## 课程购买流程
1. 判断购买意图:会话里是否已明确课程名称或已有推荐
2. 直接预下单:已明确课程 → 调用 prePlaceOrder 进入预下单流程
3. 无明确课程 → 引导进入课程推荐流程
4. 主动询问感兴趣的课程名称
5. 支持单门或多门课程购买
```

```java
@Component
@RequiredArgsConstructor
public class BuyAgent extends AbstractAgent {
    private final SystemPromptConfig systemPromptConfig;
    private final OrderTools orderTools;

    @Override
    public AgentTypeEnum getAgentType() { return AgentTypeEnum.BUY; }

    @Override
    public String systemMessage() { return systemPromptConfig.getBuyAgentSystemMessage().get(); }

    @Override
    public Object[] tools() { return new Object[]{orderTools}; }

    /** 工具上下文:带用户 id + 请求 id */
    @Override
    public Map<String, Object> toolContext(String sessionId, String requestId) {
        return Map.of(
                "userId", UserContext.getUser(),
                "requestId", requestId);
    }
}
```

测试:"下单购买,课程id为:xxx" → 返回预下单结果(订单号、金额等),同时前端收到 PARAM 事件(结构化订单数据)。

## 五、咨询智能体(RAG + 工具 + 提示词参数)

**提示词要点**:

```
# 角色:客服代表 & 讲师,提供课程咨询服务
## 课程推荐与信息查询
- 学员问课程内容 → 知识库匹配课程,拿到课程 id 查详情,回复要全面且引导报名
- 没找到 → 礼貌告知并建议联系人工客服(电话:your-support-phone)
- 问课程有效期 → 当前时间 {now} + 有效期算到期日;有效期 999 天视为永久有效
## 注意事项
- 推荐课程必须源自知识库,严禁编造
- 仅回答课程与 IT 知识相关问题
- 不能直接提供课程 id,可引导其他话题
```

```java
@Override
public Map<String, Object> systemMessageParams() {
    return Map.of("now", DateUtil.now());      // 把当前时间塞进提示词模板
}
```

> 亮点:**提示词模板带参数** `{now}`,由 `systemMessageParams()` 动态填充。

## 七、本节速记

1. 五个智能体 = **路由 + 推荐 + 购买 + 咨询 + 知识**,越通用(推荐/知识)与越业务(购买)分层;
2. 差异都体现在三处:**systemMessage()、tools()、advisors()**,其余全在抽象类复用;
3. 提示词放**配置中心**热更新,并支持 `{now}` 之类的**模板参数**;
4. 工具上下文用于传 userId/requestId,配合前端展示结构化结果;
5. 心法:先问"这个智能体需要什么能力",再决定它挂什么工具与 Advisor。
