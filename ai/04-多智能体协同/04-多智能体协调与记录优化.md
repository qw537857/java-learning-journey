# 多智能体协调与"记录优化"Bug(2026-09-11)

> 来源:AI 课程导图(12 多智能体协同工作)整理,面向 Java 初级工程师。
> 目标:把 5 个智能体"串成一条业务线",并解决一个真实 bug:路由的内部标记被记进历史记录。

---

## 一、把智能体协调起来工作

思路:**用户提问 → 路由智能体识别意图 → 找到对应智能体 → 交给它处理**。

### 1.1 用配置开关切换架构

```yaml
demo:
  ai:
    chat-type: ROUTE      # ROUTE(路由多智能体) / ENHANCE(单智能体)
```

### 1.2 AgentServiceImpl(路由模式)

```java
@Service
@RequiredArgsConstructor
@ConditionalOnProperty(prefix = "demo.ai", name = "chat-type", havingValue = "ROUTE")
public class AgentServiceImpl implements IChatService {

    @Override
    public Flux<ChatEventVO> chat(String question, String sessionId) {
        // 1. 先问路由智能体:用户想干嘛?
        var result = findAgentByType(AgentTypeEnum.ROUTE).process(question, sessionId);

        // 2. 按意图找对应智能体
        var agent = findAgentByType(AgentTypeEnum.agentNameOf(result));
        if (agent == null) {
            // 没匹配到(如问候/无关问题):把路由的自然语言回复直接返回
            var event = ChatEventVO.builder()
                    .eventType(ChatEventTypeEnum.DATA.getValue())
                    .eventData(result)
                    .build();
            return Flux.just(event, AbstractAgent.STOP_EVENT);
        }

        // 3. 交给业务智能体流式处理
        return agent.processStream(question, sessionId);
    }

    /** 按类型找 Agent:利用 Spring 容器里所有 Agent Bean */
    private Agent findAgentByType(AgentTypeEnum type) {
        if (type == null) return null;
        var beans = SpringUtil.getBeansOfType(Agent.class);      // Hutool 取容器 Bean
        for (var agent : beans.values()) {
            if (type == agent.getAgentType()) return agent;
        }
        return null;
    }

    @Override
    public void stop(String sessionId) {
        findAgentByType(AgentTypeEnum.ROUTE).stop(sessionId);
    }
}
```

### 1.3 旧实现加条件,互不冲突

```java
@Service
@ConditionalOnProperty(prefix = "demo.ai", name = "chat-type", havingValue = "ENHANCE")
public class ChatServiceImpl implements IChatService { /* 原来的单智能体实现 */ }
```

> 用 `@ConditionalOnProperty` 让两种实现**按配置二选一**,想回退单智能体改配置即可。

### 1.4 测试

推荐用能力较强的模型(如 qwen3.7-max)效果更准:

```
"课程推荐,20岁,本科,对 java 感兴趣,没有编程经验"  → 走推荐智能体
"下单购买"                                        → 走购买智能体
```

## 二、Bug:路由的内部标记被记进了历史记录

### 2.1 现象

查历史记录,发现存了这样的内容:

```json
{ "type": "USER",      "content": "课程推荐" },
{ "type": "ASSISTANT", "content": "RECOMMEND" },      ← 路由智能体的"内部指令",不该给用户看
{ "type": "USER",      "content": "课程推荐" },
{ "type": "ASSISTANT", "content": "为了给您提供最合适的课程推荐,请先提供…" }
```

原因:路由智能体处理时,会把 `RECOMMEND` 这类**内部意图标记**也写入会话记忆(Redis),
历史记录接口读出来就暴露了实现细节。

### 2.2 解决:自定义 Advisor 清理冗余记录

思路:**当大模型输出内容是智能体名称(如 RECOMMEND/BUY)时,删掉 Redis 里最近两条记录。**

```java
public class RecordOptimizationAdvisor implements BaseAdvisor {

    private final MyChatMemoryRepository myChatMemoryRepository;

    public RecordOptimizationAdvisor(MyChatMemoryRepository repo) {
        this.myChatMemoryRepository = repo;
    }

    @Override
    public ChatClientRequest before(ChatClientRequest request, AdvisorChain chain) {
        return request;
    }

    @Override
    public ChatClientResponse after(ChatClientResponse response, AdvisorChain chain) {
        var chatResponse = response.chatResponse();
        assert chatResponse != null;
        var text = chatResponse.getResult().getOutput().getText();

        // 输出内容如果是智能体名称,说明是路由的内部标记 → 清理记录
        var agentType = AgentTypeEnum.agentNameOf(text);
        if (agentType != null) {
            var conversationId = Convert.toStr(response.context().get(ChatMemory.CONVERSATION_ID));
            myChatMemoryRepository.optimization(conversationId);
        }
        return response;
    }

    /** 必须排在"会话记忆 Advisor"之前,才能在其写入后清理 */
    @Override
    public int getOrder() {
        return Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER - 100;
    }
}
```

### 2.3 仓储层实现(Redis:弹出最近 2 条)

```java
public interface MyChatMemoryRepository {
    /**
     * 优化对话记录:删除最后 2 条(路由智能体写入的"转发用"消息),
     * 保证历史消息的完整性
     */
    void optimization(String conversationId);
}

public class RedisChatMemoryRepository implements ChatMemoryRepository, MyChatMemoryRepository {

    @Override
    public void optimization(String conversationId) {
        var redisKey = getKey(conversationId);
        var listOps = stringRedisTemplate.boundListOps(redisKey);
        listOps.rightPop(2);          // 从右侧弹出两条
    }
}
```

### 2.4 注册 Advisor(注意顺序)

```java
@Bean
public ChatClient agentChatClient(DashScopeChatModel model, ChatMemory redisChatMemory,
                                  Advisor recordOptimizationAdvisor) {
    return ChatClient.builder(model)
            .defaultAdvisors(
                    SimpleLoggerAdvisor.builder().build(),
                    MessageChatMemoryAdvisor.builder(redisChatMemory).build(),
                    recordOptimizationAdvisor)      // 记录优化 Advisor
            .build();
}

@Bean
public Advisor recordOptimizationAdvisor(MyChatMemoryRepository repo) {
    return new RecordOptimizationAdvisor(repo);
}
```

### 2.5 验证

历史记录变得干净了:

```json
{ "type": "USER",      "content": "你好" },
{ "type": "ASSISTANT", "content": "您好!有什么可以帮您?" },
{ "type": "USER",      "content": "课程推荐" },
{ "type": "ASSISTANT", "content": "您好!有什么可以帮您呢?" }
```

## 三、这个 Bug 给我们的启示

| 启示 | 说明 |
|------|------|
| **多智能体要管好"中间产物"** | 路由/协调产生的内部指令,不能混进用户可见的记录 |
| **Advisor 是切面,能改流程** | 不止记日志,还能拦截输出、清理数据、控制顺序 |
| **顺序很关键** | 清理要排在写入之后(`getOrder()` 调整) |
| **存储结构决定解法** | Redis List 直接 `rightPop(2)` 最省事;换存储则要换清理逻辑 |
| **配置开关保退路** | `@ConditionalOnProperty` 让新旧架构可随时切换 |

## 四、本节速记

1. 协调 = **路由定意图 → 按类型找到智能体 → 流式执行**,用 Spring 容器收集所有 `Agent` Bean;
2. `@ConditionalOnProperty` + `chat-type` 配置,可随时在"单智能体/多智能体"间切换;
3. 典型 bug:内部意图标记(`RECOMMEND`/`BUY`)被写进会话历史;
4. 解法:自定义 `BaseAdvisor` 检测输出 → 调仓储 `optimization()` 清掉最近 2 条;
5. 记住 **Advisor 顺序**(`DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER - 100`)决定成败。
