# 路由工作流改造:Agent 接口与抽象类(2026-09-11)

> 来源:AI 课程导图(12 多智能体协同工作)整理,面向 Java 初级工程师。
> 目标:把一个"增强型单智能体"改造成"路由工作流多智能体",并打好可复用的工程骨架(枚举 + 接口 + 抽象类)。

---

## 一、改造思路

把一个"全能智能体"拆成 **5 个智能体协作**:

```
用户提问 → 【意图分析智能体(路由)】判断意图
              ↓
   ┌──────────┬──────────┬──────────┬──────────┐
 推荐智能体   咨询智能体   购买智能体   知识智能体
```

好处:**分工明确**,每个智能体只在需要时挂自己的工具/RAG,系统更灵活高效(不用所有智能体都配全套工具)。

工程上,多个智能体必然有重复代码 → 抽 **接口 + 抽象类**:

- `Agent` 接口:定义标准方法;
- `AbstractAgent` 抽象类:承载通用实现(流式处理、记忆、工具装配等)。

## 二、定义智能体类型枚举

```java
@Getter
public enum AgentTypeEnum {
    ROUTE("ROUTE", "路由智能体"),
    RECOMMEND("RECOMMEND", "课程推荐智能体"),
    CONSULT("CONSULT", "课程咨询智能体"),
    BUY("BUY", "课程购买智能体"),
    KNOWLEDGE("KNOWLEDGE", "知识讲解智能体");

    private final String agentName;
    private final String desc;

    AgentTypeEnum(String agentName, String desc) {
        this.agentName = agentName;
        this.desc = desc;
    }

    @Override
    public String toString() { return this.name(); }

    /** 通过智能体名称查找枚举(借助 Hutool EnumUtil) */
    public static AgentTypeEnum agentNameOf(String agentName) {
        return EnumUtil.getBy(AgentTypeEnum::getAgentName, agentName);
    }
}
```

> 用枚举统一管理类型,路由智能体返回的字符串(如 `RECOMMEND`)就能直接映射成 Java 枚举。

## 三、定义 Agent 接口

把每个智能体都需要的操作抽象出来:

```java
public interface Agent {
    Object[] EMPTY_OBJECTS = new Object[0];

    /** 流式对话(返回事件流) */
    Flux<ChatEventVO> processStream(String question, String sessionId);

    /** 普通对话 */
    String process(String question, String sessionId);

    /** 智能体类型 */
    AgentTypeEnum getAgentType();

    /** 停止指定会话的生成 */
    void stop(String sessionId);

    // ===== 子类按需覆盖的装配能力 =====
    default String systemMessage() { return ""; }                                   // 系统提示词
    default Object[] tools() { return EMPTY_OBJECTS; }                              // 工具集
    default Map<String, Object> toolContext(String sessionId, String requestId) { return Map.of(); }
    default List<Advisor> advisors() { return List.of(); }                          // Advisor 列表
    default Map<String, Object> advisorParams(String sessionId, String requestId) { return Map.of(); }
    default Map<String, Object> systemMessageParams() { return Map.of(); }          // 提示词参数
}
```

**设计要点**:接口只规定"做什么",**每种能力都有默认实现**,子类只覆盖自己需要的部分。

## 四、抽象类 AbstractAgent(核心骨架)

### 4.1 改造 ChatClient 配置

不再设置默认工具,只保留日志 + 会话记忆 Advisor:

```java
@Configuration
public class SpringAIConfig {
    @Bean
    public ChatClient agentChatClient(DashScopeChatModel model, ChatMemory redisChatMemory) {
        return ChatClient.builder(model)
                .defaultAdvisors(
                        SimpleLoggerAdvisor.builder().build(),
                        MessageChatMemoryAdvisor.builder(redisChatMemory).build())
                .build();
    }
}
```

> 工具由各智能体通过接口的 `tools()` 提供,而不是全局默认。

### 4.2 抽象类实现(关键逻辑)

```java
@Slf4j
public abstract class AbstractAgent implements Agent {

    @Resource private ChatClient agentChatClient;
    @Resource private ChatMemory redisChatMemory;
    @Resource private IChatSessionService chatSessionService;

    /** 输出结束标记事件 */
    public static final ChatEventVO STOP_EVENT =
            ChatEventVO.builder().eventType(ChatEventTypeEnum.STOP.getValue()).build();

    /** 记录各会话的生成状态(线程安全);分布式环境可换 Redis */
    public static final Map<String, Boolean> GENERATE_STATUS = new ConcurrentHashMap<>();

    @Override
    public String process(String question, String sessionId) {
        var requestId = generateRequestId();
        return getChatClientRequest(sessionId, requestId, question).call().content();
    }

    @Override
    public Flux<ChatEventVO> processStream(String question, String sessionId) {
        var requestId = generateRequestId();
        var outputBuilder = new StringBuilder();                 // 缓存输出(中断时可留存)
        var conversationId = IChatService.getConversationId(sessionId);

        return getChatClientRequest(sessionId, requestId, question)
                .stream()
                .chatResponse()
                .doFirst(() -> GENERATE_STATUS.put(sessionId, true))     // 开始输出
                .doOnError(t -> GENERATE_STATUS.remove(sessionId))
                .doOnComplete(() -> GENERATE_STATUS.remove(sessionId))
                .doOnCancel(() -> saveStopHistoryRecord(conversationId, outputBuilder.toString()))
                .takeWhile(r -> GENERATE_STATUS.getOrDefault(sessionId, false))   // 控制流是否继续
                .map(chatResponse -> {
                    var finishReason = chatResponse.getResult().getMetadata().getFinishReason();
                    if (StrUtil.equals("STOP", finishReason)) {
                        ToolResultHolder.put(chatResponse.getMetadata().getId(),
                                "requestId", requestId);                 // 记录工具调用参数
                    }
                    var text = chatResponse.getResult().getOutput().getText();
                    outputBuilder.append(text);
                    return ChatEventVO.builder()
                            .eventData(text)
                            .eventType(ChatEventTypeEnum.DATA.getValue())
                            .build();
                })
                .doFinally(signal -> chatSessionService.update(sessionId, outputBuilder.toString(), userId))
                .concatWith(Flux.defer(() -> {
                    // 把工具结果作为 PARAM 事件追加,最后追加 STOP 事件
                    var map = ToolResultHolder.get(requestId);
                    if (CollUtil.isNotEmpty(map)) {
                        ToolResultHolder.remove(requestId);
                        var paramEvent = ChatEventVO.builder()
                                .eventData(map)
                                .eventType(ChatEventTypeEnum.PARAM.getValue())
                                .build();
                        return Flux.just(paramEvent, STOP_EVENT);
                    }
                    return Flux.just(STOP_EVENT);
                }));
    }

    /** 统一组装请求:system / advisors / tools / toolContext / user */
    private ChatClient.ChatClientRequestSpec getChatClientRequest(String sessionId, String requestId, String question) {
        return agentChatClient.prompt()
                .system(s -> s.text(systemMessage()).params(systemMessageParams()))
                .advisors(a -> a.advisors(advisors()).params(advisorParams(sessionId, requestId)))
                .tools(tools())
                .toolContext(toolContext(sessionId, requestId))
                .user(question);
    }

    /** 停止生成 */
    @Override
    public void stop(String sessionId) {
        GENERATE_STATUS.remove(sessionId);
    }

    /** 默认把 conversationId 塞进 Advisor 参数(会话记忆需要) */
    @Override
    public Map<String, Object> advisorParams(String sessionId, String requestId) {
        return Map.of(ChatMemory.CONVERSATION_ID, IChatService.getConversationId(sessionId));
    }

    private String generateRequestId() { return IdUtil.fastSimpleUUID(); }
}
```

### 4.3 这段代码里的设计亮点(值得学)

| 点 | 说明 |
|----|------|
| `GENERATE_STATUS` + `takeWhile` | 用一个 Map 控制流:移除即"停止输出",实现**中断生成** |
| `outputBuilder` + `doOnCancel` | 用户中断时,把**已生成内容**存进会话记忆 |
| `ToolResultHolder` + `requestId` | 把工具调用产生的结构化数据**回传给前端**(PARAM 事件) |
| `concatWith` + `STOP_EVENT` | 流的结尾统一追加"结束标记",前端好判断 |
| `doFinally` | 更新会话标题/时间,保证会话列表正确 |
| 默认方法 | 接口给默认实现,子类**只覆盖需要的部分** |

## 五、本节速记

1. 路由改造 = **1 个路由智能体 + N 个业务智能体**,各挂各的工具;
2. 工程骨架:`AgentTypeEnum`(类型)+ `Agent`(标准接口)+ `AbstractAgent`(通用实现);
3. 流式处理要点:`takeWhile` 控中断、`concatWith(STOP_EVENT)` 收尾、`doOnCancel` 留痕、`doFinally` 更新会话;
4. 工具结果通过 `ToolResultHolder` + requestId 以事件形式回传前端;
5. 设计心法:**通用的沉到抽象类,差异的留给子类覆盖**。
