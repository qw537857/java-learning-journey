# 智能体的六种架构模式(2026-09-11)

> 来源:AI 课程导图(12 多智能体协同工作)整理,面向 Java 初级工程师。
> 目标:建立"智能体架构"全景认知——同一个需求可以用 6 种模式实现,知道什么时候用哪种。

---

## 〇、为什么需要"架构模式"

之前做的 AI 助理只是**最基础的一种模式**。一般应用系统的智能体架构有 6 种:

```
1. 增强型智能体
2. 链式工作流智能体
3. 路由工作流智能体   ← 本篇重点
4. 并行工作流智能体
5. 协调器工作流智能体
6. 评估优化工作流智能体
```

---

## 1.1 增强型智能体(最基础)

**构成**:一个"增强的 LLM",带**检索(Retrieval)、工具(Tools)、记忆(Memory)**三项增强能力。

```
Input → LLM(协调 检索/工具/记忆)→ Output
```

- 流程是**线性的**:输入 → 大模型 → 输出;
- 大模型像"中央处理器",统一协调三个功能模块;
- 适用:**业务不复杂**的场景(我们之前实现的单智能体 AI 助理就是这种)。

---

## 1.2 链式工作流智能体(固定步骤链)

把任务**分解成一系列步骤**,每个 LLM 调用处理上一步的输出。

- **顺序分解**:`LLM Call 1 → LLM Call 2 → LLM Call 3` 固定链路;
- **中间检查(Gate)**:某一步输出后插入校验点,阻断错误向下传播;
- **上下文传递**:Output1 → 输入 2,Output2 → 输入 3,靠链式传递保持连贯。

**适用**:任务复杂但**流程固定**。典型:写文章 → 生成大纲 → 校验大纲 → 按大纲写内容 → 内容校验 → 输出。

---

## 1.3 路由工作流智能体(本篇重点)

先用 **LLM Call Router 做意图识别**,再交给下游对应的 LLM 执行。

- **动态路径选择**:Router 根据输入特征(内容类型/用户意图)决定调用哪个 LLM;
- **集中式决策**:所有输入都先过 Router(而非直接调 LLM),降低业务模块间耦合;
- **可扩展**:图示 3 条路径,实际可随意增减分支。

**适用**:业务复杂、且**各分支处理逻辑相互独立**。例如 AI 助理:课程推荐、课程查询、课程购买、知识讲解都是独立业务,各自一个智能体。

---

## 1.4 并行工作流智能体(并发 + 聚合)

一个输入**同时**交给多个 LLM 执行,再汇总输出。

- **任务并行拆分**:Input 同时分发 LLM1/2/3,提升效率;
- **结果聚合**:Aggregator 整合多个输出,用**冗余计算**换可靠性;
- **模块化隔离**:各 LLM 无直接依赖(只连 Aggregator),降低单点故障。

**两种典型场景**:

1. 一个大任务拆成多个子任务并行(如多维度内容审核:攻击性言论、数据准确性、版权检测并行跑);
2. **同一任务交给不同大模型跑多次**,聚合得到更准结果(如医疗诊断辅助、金融风险评估)。

> 注意概念:**冗余计算**——算一遍就够,却重复多次计算,只为可靠性买单,平时是要避免的性能浪费。

---

## 1.5 协调器工作流智能体(动态调度)

由 **Orchestrator LLM** 充当智能调度中心,**动态生成子任务列表**,子任务可串行可并行,结果由 **Synthesizer** 聚合。

- **动态任务分解**:子任务不是预先写死的,而是协调器按进展动态分配/调整;
- **异构模型协同**:按子任务需要选择最合适的模型执行;
- **结果智能整合**:Synthesizer 用语义融合保证最终输出一致连贯。

**适用**:复杂且**细节不确定**的任务(比如编程中根据实际情况动态修改多个文件)。看起来像并行,但更灵活。

---

## 1.6 评估优化工作流智能体(生成→评估→反馈)

循环反馈机制:

```
生成(Generator)产出初稿
   ↓
评估(Evaluator)判断质量 → Accepted 或 Rejected+Feedback
   ↓
决策:通过 → 输出;不通过 → 带反馈重新生成(循环)
```

**适用**:对输出质量要求高、可迭代的场景。例如文学翻译:初译可能没抓住细节,评估模型给出建设性反馈后重译。

---

## 1.7 选型总结(按业务选)

| 业务特征 | 推荐模式 |
|----------|----------|
| 简单任务 | 增强型 / 链式工作流 |
| 多分支、分支独立 | **路由工作流** |
| 高实时性、任务可拆分 | 并行工作流 |
| 超复杂、细节不确定 | 协调器工作流 |
| 超高可靠性要求 | 评估优化工作流 |

---

## 本节速记

1. 六种模式:**增强 → 链式 → 路由 → 并行 → 协调器 → 评估优化**,复杂度递进;
2. 路由模式核心是"**先意图识别,再分派**",最适合业务分支独立的系统;
3. 并行 = 分发多模型 + 聚合;协调器 = 动态生成子任务;评估优化 = 生成-评估-反馈闭环;
4. 选型口诀:**简单就增强,分支就路由,要快就并行,太复杂上协调器,要稳上评估**。
