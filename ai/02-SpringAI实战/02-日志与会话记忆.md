## 一、日志功能(调试必备)

默认情况下,SpringAI 与大模型的交互**不记录日志**——我们看不到它到底拼了什么提示词,调试很痛苦。

### 1.1 Advisor:SpringAI 的"AOP 增强"

SpringAI 基于 **AOP** 实现对话过程的增强、拦截、修改,**所有增强都要实现 `Advisor` 接口**。官方默认实现:

| Advisor | 作用 |
|---------|------|
| `SimpleLoggerAdvisor` | 记录对话日志 |
| `MessageChatMemoryAdvisor` | 会话记忆 |
| `QuestionAnswerAdvisor` | 实现 RAG |

也可以自定义 Advisor(见第 03 篇的 TimeAdvisor 示例)。

### 1.2 添加日志 Advisor

```java
@Bean
public ChatClient chatClient(OllamaChatModel model) {
    return ChatClient.builder(model)
            .defaultSystem("你是一个热心、可爱的智能助手,名字叫小团团,请以小团团的身份和语气回答问题。")
            .defaultAdvisors(new SimpleLoggerAdvisor())   // 添加默认 Advisor,记录日志
            .build();
}
```

### 1.3 调整日志级别

```yaml
logging:
  level:
    org.springframework.ai.chat.client: debug   # AI 对话日志
    com.example.ai: debug                       # 本项目日志
```

重启后再聊天,就能看到完整的对话日志了。

## 二、对接前端

浏览器地址栏访问太简陋,课程提供了一套前端页面(两种运行方式)。

### 2.1 npm 运行前端

```bash
npm install
npm run dev
# 访问 http://localhost:5173
```

### 2.2 解决跨域(CORS)

前后端不同域名存在跨域,服务端要放行:

```java
@Configuration
public class MvcConfiguration implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
                .allowedOrigins("*")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .exposedHeaders("Content-Disposition");   // 文件下载要用
    }
}
```

> 前端约定:服务端地址 `http://localhost:8080`,对话接口 `POST /ai/chat`,**接口路径不要改**,前端写死了。

### 2.3 对接用 Controller

```java
@PostMapping(value = "/chat", produces = "text/html;charset=UTF-8")
public Flux<String> chat(String prompt, String chatId) {
    return chatClient
            .prompt()
            .user(prompt)
            .stream()
            .content();

```

## 三、会话记忆功能

前面讲过原理:让 AI 有记忆 = 把历史对话拼进 Prompt。**SpringAI 自带这个功能,不用自己拼。**

### 3.1 ChatMemory 接口

```java
public interface ChatMemory {
    // 添加消息到指定 conversationId 的会话历史
    void add(String conversationId, List<Message> messages);
    // 查询历史会话
    List<Message> get(String conversationId, int lastN);
    // 清除指定会话历史
    void clear(String conversationId);
}
```

- 会话记忆都以 **conversationId(会话 id)** 区分管理,不同会话互不干扰;
- 实现:`InMemoryChatMemory`(内存)/ `MessageWindowChatMemory`(带窗口,防上下文爆炸)。

### 3.2 注册 ChatMemory + 添加记忆 Advisor

```java
@Bean
public ChatMemory chatMemory() {
    return MessageWindowChatMemory.builder()
            .maxMessages(100)     // 只保留最近 100 条,防止上下文爆炸
            .build();
}

@Bean
public ChatClient chatClient(OllamaChatModel model, ChatMemory chatMemory) {
    return ChatClient.builder(model)
            .defaultSystem("你是一位友好的在线客服助手,名字叫小助手。")
            .defaultAdvisors(new SimpleLoggerAdvisor())
            .defaultAdvisors(MessageChatMemoryAdvisor.builder(chatMemory).build())  // 会话记忆
            .build();
}
```

### 3.3 Controller 必须传 chatId

```java
Flux<String> ret = chatClient
        .prompt()
        .user(prompt)
        .advisors(p -> p.param(ChatMemory.CONVERSATION_ID, chatId))  // 指定这个 chatId 的记忆
        .stream()
        .content();
```

> ⚠️ **不传 chatId 会报错**(Advisor 找不到会话标识),务必从请求参数里带过来。

## 四、会话历史(和会话记忆是两回事!)

| 概念 | 含义 |
|------|------|
| **会话记忆** | 让大模型记住**一轮会话内**的上下文(不忘记前一句) |
| **会话历史** | 记录**一共有多少个不同的会话**(即所有 chatId 的列表) |

- ChatMemory 里以 `conversationId → List<Message>` 存消息(会话记忆);
- 会话历史 = 把这些 conversationId 记下来,需要时查列表。

### 4.1 管理会话 id

```java
public interface ChatHistoryRepository {
    /** 保存会话记录 @param type 业务类型(chat/service/pdf) */
    void save(String type, String chatId);
    /** 查询会话 id 列表 */
    List<String> getChatIds(String type);
}

@Component
@RequiredArgsConstructor
public class InMemoryChatHistoryRepository implements ChatHistoryRepository {
    private final Map<String, List<String>> chatHistory = new ConcurrentHashMap<>();

    @Override
    public void save(String type, String chatId) {
        List<String> chatIds = chatHistory.computeIfAbsent(type, k -> new ArrayList<>());
        if (!chatIds.contains(chatId)) {
            chatIds.add(chatId);
        }
    }

    @Override
    public List<String> getChatIds(String type) {
        return chatHistory.getOrDefault(type, List.of());
    }
}
```

> 生产建议:会话 id 关系统一持久化到 Redis / MySQL;有用户概念时还要记 userId、时间。

### 4.2 保存 + 查询会话历史

```java
// 1) 聊天时顺手记录 chatId
@RequestMapping(value = "/chat", produces = "text/html;charset=UTF-8")
public Flux<String> chat(@RequestParam(defaultValue = "讲个笑话") String prompt, String chatId) {
    chatHistoryRepository.save("chat", chatId);          // 保存会话历史
    return chatClient.prompt(prompt)
            .advisors(a -> a.param(ChatMemory.CONVERSATION_ID, chatId))  // 传会话记忆 id
            .stream()
            .content();
}

// 2) 查会话历史列表 + 某个会话的全部消息
@GetMapping("/{type}")
public List<String> getChatIds(@PathVariable String type) {
    return chatHistoryRepository.getChatIds(type);
}

@GetMapping("/{type}/{chatId}")
public List<MessageVO> getChatHistory(@PathVariable String type, @PathVariable String chatId) {
    List<Message> messages = chatMemory.get(chatId, Integer.MAX_VALUE);
    return messages == null ? List.of() : messages.stream().map(MessageVO::new).toList();
}
```

MessageVO 的作用:把 SpringAI 的 `Message` 转成前端要的 `{role, content}`:

```java
@Data
public class MessageVO {
    private String role;
    private String content;

    public MessageVO(Message message) {
        this.role = switch (message.getMessageType()) {
            case USER -> "user";
            case ASSISTANT -> "assistant";
            case SYSTEM -> "system";
            default -> "";
        };
        this.content = message.getText();
    }
}
```
