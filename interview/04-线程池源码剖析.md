## 一、线程池基础

### 1.1 什么是线程池

一种多线程处理形式:把**任务**放到队列,线程池创建线程后自动启动这些任务。

- 线程:前面学的 Thread;
- 任务:实现了 Runnable 或 Callable 的实例对象。

### 1.2 为什么需要线程池

最大原因:**根据系统需求和硬件环境灵活控制线程数量,统一管理所有线程**,提高系统运行效率、降低运行压力。

### 1.3 优势(面试背这 3 条)

1. **线程和任务分离,提升线程重用性**(不用每次 new Thread);
2. **控制并发数量,降低服务器压力**,统一管理线程;
3. **提升响应速度**:设创建线程耗时 T1、执行任务 T2、销毁线程 T3,线程池免去了 T1 和 T3。

### 1.4 典型应用场景

- 云盘文件上传 / 下载;
- 多线程批量发短信、邮件;
- 各种框架内部用多线程提升效率。

## 二、ThreadPoolExecutor 七大参数

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
        2,                          // 1. corePoolSize 核心线程数
        4,                          // 2. maximumPoolSize 最大线程数
        60, TimeUnit.SECONDS,       // 3. keepAliveTime 非核心线程空闲存活时间
        new ArrayBlockingQueue<>(10), // 4. workQueue 任务阻塞队列
        new ThreadFactory() {       // 5. threadFactory 线程工厂
            int count;
            @Override
            public Thread newThread(Runnable r) {
                return new Thread(r, "worker-" + count++);
            }
        },
        new ThreadPoolExecutor.DiscardPolicy()); // 6/7. handler 拒绝策略

// 提交 16 个任务验证执行流程
for (int i = 0; i < 16; i++) {
    final int x = i;
    executor.execute(() ->
        System.out.println("线程:" + Thread.currentThread().getName() + ", 任务序号:" + x));
}
executor.shutdown();
```

### 2.1 参数逐个讲

| 参数 | 含义 |
|------|------|
| **corePoolSize** | 核心线程数:常驻线程,可闲置不回收 |
| **maximumPoolSize** | 最大线程数:核心 + 非核心(临时)线程的总上限 |
| **keepAliveTime** | 非核心线程的存活时间:队列空了、也没新任务时,临时线程等这么久就被回收 |
| **workQueue** | 任务阻塞队列:核心线程满了,新任务先排队 |
| **threadFactory** | 线程工厂:负责创建线程(建议起有意义的名字,方便排查问题) |
| **handler** | 拒绝策略:队列满 + 线程达上限时怎么处理新任务 |

### 2.2 四种拒绝策略

| 策略 | 行为 |
|------|------|
| **AbortPolicy**(默认) | 丢弃任务并抛 `RejectedExecutionException` |
| **DiscardPolicy** | 丢弃任务,不抛异常(静默丢,要慎用) |
| **DiscardOldestPolicy** | 丢弃队列最前面的任务,再重新尝试执行新任务 |
| **CallerRunsPolicy** | 不丢弃,由**提交任务的调用线程**自己执行(降速保任务) |

### 2.3 执行流程(核心链路,背下来)

```
提交任务
  ↓
工作线程数 < corePoolSize? ──是──→ 新建核心线程执行(此时不重用旧线程)
  ↓否
任务放入阻塞队列等待(核心线程忙完再来取)
  ↓
队列已满 且 工作线程数 < maximumPoolSize? ──是──→ 新建非核心(临时)线程执行
  ↓否
执行拒绝策略(handler)
```

> 注意细节:只要工作线程数没到 corePoolSize,来一个任务就新建一个线程,不会复用;达到 corePoolSize 后,新任务一律先进队列。

## 三、参数设计分析(面试问"线程池参数怎么定")

背景题:执行一个任务要 0.1 秒,系统 80% 时间每秒产生 100 个任务。

| 参数 | 设计思路 | 例子 |
|------|----------|------|
| **corePoolSize** | 按 80% 场景设计,让 1 秒内能处理完常规任务量 | 每秒 100 任务 × 0.1 秒 → 核心线程 10;一般按 **8020 原则**设计,剩下 20% 用最大线程扛 |
| **workQueue** | `核心线程数 / 单个任务耗时 × 2` | 10 / 0.1 × 2 = 队列长度 200 |
| **maximumPoolSize** | 参照每秒**最大**任务数:`(最大任务数 - 队列长度) × 单个任务耗时` | 每秒最多 1000 任务 → (1000 - 200) × 0.1 = 80 |
| **keepAliveTime** | 依据系统环境和任务产生间隔灵活设置,无固定值 | 经验值即可 |

**行业经验公式(常考):**

- **CPU 密集型**:核心线程数 = **CPU 核数 + 1**(计算不吃 I/O,线程多了反而频繁切换);
- **IO 密集型**:核心线程数 = **2 × CPU 核数**(线程大部分时间在等 I/O,可以多开)。

## 四、线程池源码:五种状态与 ctl

### 4.1 五种状态

| 状态 | 含义 | 流转 |
|------|------|------|
| **RUNNING** | 运行中:能接新任务,也能处理队列任务 | 初始状态;执行 shutdown → SHUTDOWN;执行 shutdownNow → STOP |
| **SHUTDOWN** | 待关闭:**不再接新任务**,继续处理队列里的任务 | 队列空且工作线程数为 0 → TIDYING |
| **STOP** | 停止:不接新任务、不处理队列任务,并尝试**中断执行中**的任务 | 工作线程数为 0 → TIDYING |
| **TIDYING** | 整理:任务都执行完,工作线程也为 0 | 执行 terminated() → TERMINATED |
| **TERMINATED** | 终止:完全终止,资源释放完毕 | 终点 |

### 4.2 ctl:一个 int 存两个值(源码精妙点)

ThreadPoolExecutor 里只用了一个 `AtomicInteger ctl` 就同时保存了**线程池状态 + 工作线程数量**:

- 高 3 位存状态(5 种状态用 3 位足够),低 29 位存线程数;
- 用位运算拆分,保证两个值一起**原子更新**(CAS),避免状态和数量不一致。

> 面试亮点:能说出"用一个 AtomicInteger 高 3 位存状态、低 29 位存 worker 数,靠位运算 + CAS 原子更新",比背概念强很多。

## 五、ExecutorService 工具类与 Executors

### 5.1 接口方法

| 方法 | 作用 |
|------|------|
| `shutdown()` | 顺序关闭:执行完已提交任务,**不再接受新任务** |
| `shutdownNow()` | 停止所有执行中的任务,暂停等待的任务,**返回等待执行的任务列表** |
| `submit(Callable<T>)` | 执行带返回值任务,返回 Future |
| `submit(Runnable)` | 执行 Runnable,返回 Future |
| `submit(Runnable, T result)` | 执行完返回指定的 result |

### 5.2 Executors 常用工厂

| 工厂 | 特点 |
|------|------|
| `newCachedThreadPool()` | 可重用线程,**首次使用时才创建**,空闲线程自动回收(适合大量短期任务) |
| `newFixedThreadPool(n)` | 固定线程数的线程池 |
| `newSingleThreadExecutor()` | 单 worker 线程 + 无界队列 |
| `newScheduledThreadPool(n)` | 可延迟 / 定期执行任务 |
| `newSingleThreadScheduledExecutor()` | 单线程版定时执行 |

ScheduledThreadPool 的四个方法:

- `schedule(callable, delay, unit)` / `schedule(command, delay, unit)`:延迟 delay 时间后执行一次;
- `scheduleAtFixedRate(command, initialDelay, period, unit)`:延迟 initialDelay 后,**每间隔 period** 重复执行(固定频率);
- `scheduleWithFixedDelay(command, initialDelay, delay, unit)`:首次延迟后执行,**每次执行结束到下次开始**之间固定延迟。

> 阿里规约提醒:生产不建议直接用 Executors 的快捷方法(如 newFixedThreadPool 的队列无界、newCachedThreadPool 最大线程数近乎无限),**推荐手动 new ThreadPoolExecutor** 显式传参,防止 OOM / 线程失控。

### 5.3 Future:异步计算结果

Future 描述异步计算的结果:

| 方法 | 作用 |
|------|------|
| `get()` | 等待计算完成,获取结果(会阻塞) |
| `get(timeout, unit)` | 最多等这么久,拿不到就超时返回 |
| `cancel(boolean)` | 试图取消任务 |
| `isCancelled()` | 是否在正常完成前被取消 |
| `isDone()` | 是否已完成 |
